SlamFrames v1.0.0
- First stable release baseline.
- Promoted the author's current tested SavedVariables profile to the fresh-install and Reset defaults.
- Default Dark skin, 0.60 frame scales, ~90% bar lengths, tuned portrait zoom, text sizes, aura size/spacing/timer, effects, and cast-bar layout.
- Existing users keep their current SavedVariables; the new defaults do not overwrite established profiles.
- Experimental aura Sweep remains retired; numeric aura Timer is the supported 1.0 display.
- Preserved parked cast-bar Style 2 assets for possible future development without exposing the unfinished style in the 1.0 UI.

SlamFrames v0.19.27
- Removed the experimental Target Aura Sweep feature and its settings/command for now.
- Target aura timing is now numeric Timer-only, avoiding the broken radial cooldown path.
- Added a Timer size slider under Layout > Target aura icons.
- Timer size ranges from 50% to 200% and updates live.
- Added /sf auratimerscale (or /sf auratimersize) for direct numeric adjustment.
- Old saved Sweep settings are forced off for compatibility.

SlamFrames v0.19.26
- Fixed Target Aura Sweep still appearing as a second numeric timer.
- Sweep now uses only the native Blizzard radial cooldown model.
- The sweep cooldown frame opts out of pfUI/cooldown-count text injection via noCooldownCount.
- Timer is now a separate SlamFrames centered countdown and no longer depends on the cooldown model.
- Increased the Timer text size to match the larger centered countdown appearance requested.
- Sweep and Timer can still be enabled independently or together.

SlamFrames v0.19.25
- Fixed Target Aura Timer/Sweep behavior: Timer now uses the same native/pfUI cooldown countdown that was previously appearing under Sweep.
- Sweep now controls only the radial cooldown animation; Timer controls only the centered countdown number.
- Sweep and Timer can still be enabled independently or together.
- Removed the unwanted bottom custom timer text when the native/pfUI timer is available.

SlamFrames v0.19.24
- Replaced the unavailable ClassicAPI target-aura timing path with Nampower/SuperWoW-aware tracking.
- Nampower AURA_CAST_ON_SELF/OTHER durationMs now seeds exact GUID + spell timers for live buffs/debuffs.
- Nampower BUFF/DEBUFF ADDED/REMOVED events maintain live per-GUID aura timing state and use GetSpellDuration as a generic fallback.
- SuperWoW UNIT_CASTEVENT provides a conservative pending-cast fallback that is only promoted after the aura is actually visible on the target.
- Live target aura rendering now joins UnitBuff/UnitDebuff spell IDs to the exact-GUID timing cache, following the same cache principle used successfully by SlamPlates.
- /sf auradiag now reports SuperWoW/Nampower availability, custom-event counts, target GUID, first aura duration/remaining time, and timing source.
- Existing auras that were already active before SlamFrames observed an application may remain icon-only until refreshed/reapplied; newly observed applications can be timed exactly.

- Timer text now uses real live remaining time when ClassicAPI has observed the aura application.
- Added /sf auradiag to report whether live target aura timing data is available.

SlamFrames v0.19.11
- Fixed the Vanilla native CastingBarFrame timing reader: ordinary casts store maxValue as an absolute end timestamp, not a duration. This was the source of ~600-second/uptime values and bars that did not animate correctly.
- Fixed legacy SPELLCAST_CHANNEL_START argument order (arg1=duration ms, arg2=spell name). This is especially important for bandages and other channeled item actions.
- Active channels now ignore legacy SPELLCAST_STOP and wait for SPELLCAST_CHANNEL_STOP, preventing bandage bars from being cleared at channel start.
- SPELLCAST_CHANNEL_UPDATE now uses arg1 as remaining milliseconds when no C_Spell/native timing is available.
- Active casts now continuously reconcile against C_Spell first and the native Blizzard cast-frame timestamps second.

SlamFrames v0.19.10
- Fixed player cast timing for bandages and other item/action casts that can use a different OctoWoW event path than normal spellbook casts.
- Cast timing now resolves in order from C_Spell exact timing, Blizzard's hidden native CastingBarFrame state, then a normalized legacy SPELLCAST duration.
- Legacy duration fallback now accepts both milliseconds (8000) and seconds (8), preventing long item casts from becoming near-instant bars.
- Removed the old permanent UNIT_SPELLCAST-vs-SPELLCAST lockout so legacy-only item casts continue to work after normal spell casts.
- Added short post-start timing reconciliation so item/gathering/bandage casts can correct themselves to the engine's canonical duration on the next frame.
- Delayed casts/channels now resync exact timing where possible instead of assuming every legacy delay value is milliseconds.
